# エグゼクティブサマリー

## EHDSの本質と戦略的意義

欧州健康データ空間（European Health Data Space, EHDS）は、EUが推進する野心的な医療データエコシステム構想です。2025年の施行を控え、以下の3つの観点から戦略的重要性を持ちます。

### デジタル単一市場の中核インフラ
EHDSは、EU加盟27カ国、5億人の市民の健康データを統合的に管理・活用する基盤として設計されています。これは単なる技術プラットフォームではなく、EUのデジタル主権確立とデータ経済振興の中核戦略です[EU-GOV-001]。

### 患者中心と産業振興の両立
EHDSは「患者の権利強化」と「医療イノベーション促進」という、従来相反しがちな目標の両立を目指しています。一次利用（患者の医療）では国境を越えた医療サービスの継続性を、二次利用（研究・開発）では厳格なプライバシー保護下でのデータ活用を実現します[EU-GOV-002]。

### 世界標準への影響力
GDPRが世界のプライバシー規制の標準となったように、EHDSは医療データガバナンスの世界標準となる可能性が高いです。特にHL7 FHIRを中心とした技術標準の採用により、グローバルな相互運用性を視野に入れています[TECH-001]。

## 日本企業にとってのビジネス機会

### 市場規模と成長性
欧州委員会の推計によると、EHDSがもたらす経済効果は2030年までに年間500億ユーロに達します[EU-GOV-003]。これは以下の領域で創出されます：

1. **医療AIソリューション市場**: 150億ユーロ
   - 診断支援システム
   - 予測分析ツール
   - 個別化医療アプリケーション

2. **データ管理インフラ市場**: 200億ユーロ
   - FHIR実装サービス
   - プライバシー保護技術
   - データ品質管理ツール

3. **研究開発支援サービス**: 150億ユーロ
   - Real World Evidence生成
   - 臨床試験最適化
   - 創薬ターゲット探索

### 参入可能な事業領域

日本企業が優位性を発揮できる分野として、以下が特定されています：

**技術ソリューション提供**
- 高度な画像診断AI（日本の強み）
- 電子カルテ統合ソリューション
- セキュアなデータ連携基盤

**専門サービス**
- EHDS規制コンプライアンス支援
- データ品質保証サービス
- 多言語対応医療翻訳

**研究開発パートナーシップ**
- 希少疾患研究での日欧協力
- がん領域でのデータ共有
- 高齢化対策での知見共有

## 日本政府への政策提言（要点）

### 1. 医療データ基本法の制定
現在の次世代医療基盤法を発展させ、包括的な医療データ活用の法的枠組みを構築することが急務です。EHDSのような統一的な規制により、データ活用の予見可能性と信頼性を高める必要があります。

### 2. 国際相互運用性の確保
HL7 FHIRを中心とした国際標準への準拠を加速し、将来的な日欧データ連携を視野に入れた技術基盤を整備すべきです。これにより、日本の医療データの価値を国際的に最大化できます。

### 3. 官民連携プラットフォームの構築
EHDSのHealthData@EUに相当する、研究開発目的でのデータ活用プラットフォームを官民連携で構築し、イノベーションエコシステムを形成することが重要です。

### 4. 投資必要額と期待効果
- **初期投資**: 500-700億円（インフラ構築、制度設計）
- **年間運用費**: 100-150億円
- **期待経済効果**: 2030年までに年間1兆円規模の新市場創出

# 第1章：EHDSの概要と背景

## 1.1 EHDSとは何か

### 背景と動機

欧州健康データ空間（EHDS）構想は、2020年のCOVID-19パンデミックを契機に加速しました。パンデミック初期、EU加盟国間での医療データ共有の困難さが、効果的な対策の障害となりました[EU-GOV-004]。この経験から、以下の必要性が明確になりました：

1. **迅速なデータ共有メカニズム**
   - リアルタイムの疫学データ収集
   - 治療効果の比較分析
   - ワクチン副反応モニタリング

2. **標準化されたデータ形式**
   - 各国の異なるシステム間での相互運用性
   - 多言語対応
   - 統一的な品質基準

3. **市民の信頼確保**
   - プライバシー保護の保証
   - データ利用の透明性
   - 市民による制御権

### EUデジタル戦略における位置づけ

EHDSは、より広範なEUデジタル戦略の一部として位置づけられています[EU-GOV-005]：

**European Data Strategy（2020年）**
EHDSは、9つのセクター別データ空間の1つとして、最優先で実装が進められています。他のデータ空間（製造業、農業、金融等）のモデルケースとしても機能します。

**Digital Single Market戦略**
27カ国の市場を統合し、デジタル経済の規模の利益を実現します。医療データは、この統合市場で最も価値の高いデータ資産の1つです。

**Europe's Beating Cancer Plan**
がん撲滅計画との連携により、がん研究・治療のデータ基盤としてEHDSが活用されます。特に、希少がんの症例データ収集で効果を発揮します。

### 2025-2030年の展開ロードマップ

EHDSの実装は段階的に進められます[EU-GOV-006]：

**2025年：規則施行と基礎整備**
- EHDS規則の正式発効
- 各国の実装計画策定
- パイロットプロジェクト開始

**2026年：中核機能の稼働**
- MyHealth@EUの全面展開
- 電子処方箋の越境利用開始
- 患者サマリーの共有開始

**2027年：全加盟国接続**
- 27カ国すべての接続完了
- HealthData@EUパイロット開始
- 最初の二次利用プロジェクト

**2028-2029年：機能拡張**
- 画像データ共有開始
- AIツールの統合
- 第三国との接続検討

**2030年：完全運用と評価**
- 全機能の本格稼働
- 経済効果の評価
- 次期計画の策定

## 1.2 二つの利用形態

### 一次利用：患者中心の医療データ活用

一次利用は、直接的な医療提供を目的としたデータ活用です[EU-GOV-007]。

**越境医療での活用**
EU市民が他の加盟国で医療を受ける際、以下のデータにアクセス可能になります：
- 既往歴、アレルギー情報
- 現在の処方薬リスト
- 最近の検査結果
- 予防接種記録

**電子処方箋システム**
フィンランドで処方された薬を、スペインの薬局で受け取ることが可能になります。これには以下の標準化が必要です：
- 医薬品コードの統一（ATC分類）
- 用法用量の標準表記
- 保険適用ルールの調整

**緊急医療での活用**
事故や急病時、患者の同意能力がない場合でも、医療従事者は必要最小限の医療情報にアクセスできます。これにより、薬物相互作用や禁忌の確認が可能になります。

### 二次利用：研究・イノベーション・政策立案

二次利用は、医療の質向上と イノベーション創出を目的とします[EU-GOV-008]。

**研究開発での活用**
- **臨床研究**: 大規模コホート研究、疾患レジストリ
- **創薬開発**: ターゲット探索、バイオマーカー開発
- **医療AI開発**: 診断支援、予後予測モデル

**政策立案での活用**
- 医療資源の最適配分
- 医療費抑制策の効果測定
- パンデミック対策の立案

**品質改善での活用**
- 医療機関のベンチマーキング
- 治療アウトカムの比較
- ベストプラクティスの特定

# 第2章：規制・法的フレームワーク

## 2.1 法的基盤

### GDPRとの関係

EHDSは、一般データ保護規則（GDPR）の特別法として位置づけられます[LAW-001]。

**健康データの特別な地位**
GDPRでは、健康データは「特別カテゴリーの個人データ」として、最も厳格な保護対象となっています。EHDSは、この保護を維持しながら、適切な活用を可能にする枠組みを提供します。

**法的根拠の明確化**
- **第6条（処理の適法性）**: 公共の利益、正当な利益
- **第9条（特別カテゴリー）**: 公衆衛生、科学研究
- **第89条（保護措置）**: 仮名化、最小化

**データ主体の権利の拡張**
EHDSは、GDPRの権利に加えて、以下を追加します：
- 医療データの即時アクセス権
- 他の医療提供者への転送権
- 研究利用の選択的許可

### 関連EU法との連携

**AI Act（人工知能法）**[LAW-002]
医療AIは「高リスクAI」に分類され、以下が要求されます：
- 事前の適合性評価
- 継続的な性能モニタリング
- 説明可能性の確保
- バイアスの防止

**Data Act（データ法）**[LAW-003]
医療機器が生成するデータの共有義務：
- 機器メーカーのデータ提供義務
- 相互運用性の確保
- ベンダーロックインの防止

**Data Governance Act（データガバナンス法）**[LAW-004]
データ仲介サービスの規制：
- 中立性の要求
- セキュリティ基準
- 透明性の確保

### 各国実装の裁量範囲

**必須要件と任意要件**
- **必須**: 基本的な権利保障、技術標準、セキュリティ要件
- **任意**: 組織体制、料金設定、追加サービス

**既存制度との調整**
各国は、既存の医療制度や個人情報保護法との整合性を確保する必要があります。特に、連邦制国家（ドイツ、ベルギー等）では、地方分権との調整が課題となります。

## 2.2 データガバナンス

### データ品質要件

EHDSは、医療データの品質に関して厳格な要件を設定しています[TECH-002]。

**品質指標**
1. **完全性（Completeness）**: 必須項目の充足率95%以上
2. **正確性（Accuracy）**: エラー率1%未満
3. **一貫性（Consistency）**: 論理的矛盾の排除
4. **適時性（Timeliness）**: 24時間以内の更新

**品質保証プロセス**
- 入力時の自動検証
- 定期的な品質監査
- 継続的な改善活動
- インセンティブ制度

### アクセス権限管理

**目的制限の原則**
データアクセスは、事前に定められた目的に限定されます：
- 一次利用：直接的な医療提供
- 二次利用：承認された研究・開発

**アクセス申請プロセス**
1. 利用目的の明確化
2. 倫理審査
3. データ保護影響評価
4. アクセス権付与
5. 利用状況モニタリング

**最小権限の原則**
必要最小限のデータのみにアクセスを限定：
- 時間的制限（プロジェクト期間）
- 空間的制限（必要なデータセット）
- 機能的制限（閲覧のみ、分析可能等）

### オプトアウト制度

**対象と範囲**
市民は、以下についてオプトアウト可能です：
- 二次利用全般
- 特定の利用目的（商業研究等）
- 特定のデータカテゴリー（遺伝子データ等）

**例外規定**
以下の場合、オプトアウトが制限されます：
- 公衆衛生上の緊急事態
- 法的義務（感染症報告等）
- 生命に関わる緊急医療

## 2.3 コンプライアンス要件

### 認証・認定制度

**EHRシステム認証**[TECH-003]
電子健康記録システムは、以下の認証が必要です：
- 相互運用性テスト
- セキュリティ評価
- ユーザビリティ審査

**ウェルネスアプリ認証**
消費者向け健康アプリの任意認証制度：
- データ品質保証
- プライバシー保護
- 医学的妥当性

### 罰則規定

**行政罰**
- 最大2000万ユーロ
- 年間売上高の4%
- いずれか高い方

**是正措置**
- 処理の停止命令
- データ削除命令
- 認証取消

**民事責任**
- 損害賠償請求権
- 集団訴訟の可能性
- 立証責任の転換

# 第3章：技術アーキテクチャと実装

## 3.1 技術インフラストラクチャ

### 技術スタック階層の全体像

EHDSの技術インフラは、明確に定義された階層構造として設計されています。各階層は特定の責務を持ち、全体として統合された医療データ空間を形成します[TECH-004]。

**階層構造**
1. **データ層**：医療機関のEHR、画像診断システム、検査システム等（→4.1 Findataの実装例参照）
2. **標準化層**：FHIR変換、用語マッピング（→3.2 相互運用性フレームワーク参照）
3. **セキュリティ層**：認証・暗号化・監査（→3.3 セキュリティ技術参照）
4. **相互運用層**：National Contact Point、EU Gateway
5. **サービス層**：MyHealth@EU（一次利用）、HealthData@EU（二次利用）

### MyHealth@EU（一次利用基盤）

MyHealth@EUは、越境医療サービスを支える技術基盤で、上記階層構造のサービス層に位置します[TECH-004]。

**アーキテクチャ概要**
```
[患者端末] <-> [医療機関システム] <-> [National Contact Point] 
                                            |
                                    [EU Gateway]
                                            |
                        [他国 National Contact Point] <-> [他国医療機関]
```

**主要コンポーネント**
1. **National Contact Point (NCP)**
   - 各国のゲートウェイ
   - 認証・認可サービス
   - データ変換・翻訳

2. **eHealth Digital Service Infrastructure (eHDSI)**
   - 中央ルーティング
   - ロギング・監査
   - サービスレジストリ

**実装済みサービス**
- **Patient Summary**: 22カ国で稼働
- **ePrescription**: 10カ国で稼働
- **計画中**: 画像データ、検査結果、退院サマリー

### HealthData@EU（二次利用基盤）

HealthData@EUは、研究開発のためのセキュアなデータ処理環境で、技術スタック階層のサービス層における二次利用部分を担います[TECH-005]。

**分散型アーキテクチャ**
データを中央に集約せず、各国のノードで処理：
- データは元の場所に保持
- 分析クエリが各ノードで実行
- 結果のみが集約

**Secure Processing Environment (SPE)**
- 隔離された計算環境
- データのダウンロード不可
- 承認されたツールのみ利用可能
- 全操作の監査ログ

**メタデータカタログ**
- データセットの発見
- スキーマ情報
- 品質指標
- 利用条件

## 3.2 相互運用性フレームワーク

本セクションでは、技術スタック階層の標準化層（→3.1参照）における具体的な実装を詳述します。

### HL7 FHIR標準の採用

EHDSは、HL7 FHIR R4を中核的な標準として採用しています[TECH-006]。これは技術スタックの標準化層の基盤技術となります。

**必須FHIRリソース**
```
Patient（患者）
├── Identifier（識別子）
├── Name（氏名）
├── BirthDate（生年月日）
└── Address（住所）

Observation（観察）
├── Code（検査項目）
├── Value（結果値）
├── EffectiveDateTime（実施日時）
└── Performer（実施者）

MedicationRequest（処方）
├── Medication（薬剤）
├── Dosage（用法用量）
├── DispenseRequest（調剤指示）
└── Substitution（代替可否）
```

**技術的特徴**[TECH-006][TECH-001]
- **RESTful設計**: REST成熟度モデルのLevel 2準拠、Level 3拡張可能[TECH-001]
- **データ形式**: JSON、XML、RDFをサポート[TECH-006]
- **リソース構造**: モジュール型の再利用可能コンポーネント[TECH-001]
- **拡張機能**: Extensionメカニズムによる柔軟なカスタマイズ[TECH-006]

**European FHIR Profiles**
EU共通の制約とextension：
- 多言語対応（display要素）
- EU特有のコード体系
- プライバシーマーカー

### European EHR Exchange Format (EEHRxF)

EEHRxFは、FHIR上に構築された欧州共通フォーマットです[TECH-007]。

**6つの優先ユースケース**
1. Patient Summary（患者サマリー）
2. ePrescription/eDispensation（電子処方・調剤）
3. Laboratory Results（検査結果）
4. Medical Images（医用画像）
5. Discharge Reports（退院サマリー）
6. Rare Diseases（希少疾患）

**実装要件**
- FHIR R4準拠
- 指定されたterminologyの使用
- 最小データセットの保証
- 各国拡張の許可（80/20ルール）

### 用語・コード体系の標準化

**必須terminology**
- **SNOMED CT**: 臨床用語（診断、処置、症状）
- **ICD-10/11**: 疾病分類
- **LOINC**: 検査項目
- **ATC**: 医薬品分類
- **UCUM**: 単位

**多言語対応**
24のEU公用語への対応：
- 自動翻訳サービス
- 検証済み翻訳辞書
- フォールバック機構

## 3.3 セキュリティとプライバシー保護技術

本セクションでは、技術スタック階層のセキュリティ層（→3.1参照）における実装技術を説明します。

### 高度なプライバシー保護技術

**連合学習（Federated Learning）**[TECH-008]
```python
# 概念的な実装例
class FederatedNode:
    def train_local_model(self, local_data):
        model = initialize_model()
        model.fit(local_data)
        return model.get_weights()
    
    def aggregate_models(self, weight_list):
        return average_weights(weight_list)
```

利点：
- データの移動不要
- プライバシー保護
- 規制compliance

課題：
- 通信オーバーヘッド
- 収束の遅さ
- データ品質の不均一性

**差分プライバシー（Differential Privacy）**
ノイズ付加によるプライバシー保護：
```
実際の値 + Laplace(感度/ε) = 公開値
```
- ε（イプシロン）: プライバシー予算
- 小さいε = 高プライバシー、低精度
- 大きいε = 低プライバシー、高精度

**準同型暗号（Homomorphic Encryption）**
暗号化したまま計算可能：
- 完全準同型暗号（FHE）: 任意の計算
- 部分準同型暗号（PHE）: 加算または乗算
- トレードオフ: セキュリティvs計算コスト

### 実装における課題と対策

**スケーラビリティ**
- 27カ国、5億人のデータ処理
- ピーク時の負荷分散
- 災害復旧計画

**レガシーシステムとの統合**
- アダプター層の実装
- 段階的移行戦略
- 後方互換性の維持

# 結論と今後の展望

## EHDSが示す医療データの未来

欧州健康データ空間（EHDS）は、医療データ活用の新たなパラダイムを提示しています。それは、「データ保護」と「データ活用」を両立させ、患者の権利を守りながらイノベーションを促進する枠組みです。

### 重要な示唆

1. **規制のイノベーション**
EHDSは、規制自体がイノベーションのドライバーとなることを示しています。明確なルールと予見可能性が、企業の投資を促進し、新たな市場を創出します。

2. **技術標準の重要性**
HL7 FHIRを中心とした国際標準の採用により、真の相互運用性が実現可能になります。これは、データの価値を最大化する鍵となります。

3. **信頼の構築**
市民の信頼なくして、医療データエコシステムは機能しません。透明性、説明責任、市民参加が不可欠です。

## 日本の取るべき道

日本は、独自の強みを活かしながら、国際的な潮流に対応する必要があります。

### 短期的優先事項

1. **法制度の整備**
医療データ基本法の制定により、包括的な枠組みを構築する。

2. **技術基盤の構築**
HL7 FHIRベースの全国医療情報プラットフォームを実現する。

3. **人材育成**
医療データサイエンティスト、プライバシーエンジニアを育成する。

### 中長期的ビジョン

**アジア太平洋地域のリーダーシップ**
日本は、高度な医療技術と均質な医療サービスを基盤に、アジア太平洋地域の医療データ連携を主導すべきです。これにより、10億人規模の医療データエコシステムを構築できます。

**Society 5.0の実現**
医療データスペースは、Society 5.0の中核インフラとなります。AIと医療データの融合により、予防医療、個別化医療、健康寿命延伸を実現します。

## 行動への呼びかけ

### 政府・政策立案者へ

- 医療データ基本法の早期制定
- 十分な予算確保と投資
- 国際連携の推進

### 医療機関・医療従事者へ

- エコシステムへの参加

### 市民・患者へ

- 権利の適切な行使
- 建設的な対話への参加

## 最後に

医療データは、21世紀の最も重要な資源の一つです。EHDSは、この資源を人類の福祉向上のために活用する一つのモデルを示しています。日本は、この動きを注視し、学び、そして独自の貢献をすることで、グローバルな医療データエコシステムの一員として、人類の健康と幸福に貢献できるでしょう。
